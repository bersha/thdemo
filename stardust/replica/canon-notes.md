## Conventions for later archetypes
- `<main id="content">` wraps the page content (gate `--main "main"` on both sides); keep the live wrappers
  `.th-content-area-hero` (hero) and `.th-content-area` (sections) so the stripe/padding rules apply.
- Keep the source th-* class names in markup; author per-archetype CSS only for modules canon lacks, in `<type>.css`.
- Copy strings verbatim from `current/pages/<slug>.json` / the captured HTML (watch U+202F narrow no-break spaces, e.g. "80 000").
- Live renders hidden app states (error `h2 "Ett oväntat fel har inträffat"`, loaders, dialogs, popovers): content-diff counts
  them even when hidden — include them hidden, as live does.
- Images: lift `srcset`/`sizes` per breakpoint (hero uses 480/750/1024/1536w renditions with rxy focal crops — a single
  desktop file cost 12.5% in the 360 hero band). Harvest renditions into `assets/img/` and extend `map.json`.

## Lessons
- Headings: on the home page ONLY the hero `h1.th-hero__heading` computes to ApexNew (R-01 applies). Section h2s,
  card h3s, quick-facts h2s, tab headings, CTA-image h2s, footer headers all compute to **arial** — measure each new
  heading before applying the display stack.
- Gate flags needed on every round: `--consent "#accept-recommended-btn-handler"` (OneTrust shows its preference-center
  modal as the first layer; the built-in candidates and `#onetrust-accept-btn-handler` miss it — a dark scrim over the
  whole live capture read as 79% diff) and `--dismiss "button[aria-label='Stäng SHL-erbjudandet']"` (tag-injected SHL
  flyout, fixed bottom-right). Delete `gates/<slug>-<w>/live.png` + `chrome-live.json` when changing these flags.
- `stardust/current/measure/<slug>-units.json` is not width-keyed: delete it between the 1440 and 360 `--full` rounds and
  never run the two widths' `--full` rounds concurrently, or unit-geometry compares 360 live geometry against 1440.
- The SHL flyout timing makes content-diff/chrome-parity read it on one side only; the reasons are recorded in
  `stardust/replica/accepted.json` (applies to every page that shows the flyout).
- `measure.mjs` text snippets are capped at 40 chars — fetch full strings from the capture HTML, not the probe.
